# 条款引用校验台

本地运行的中文法规条款编号与交叉引用校验工具。粘贴含「第 X 条 / 款 / 项」编号与交叉引用的条款文本，系统自动解析为可折叠的 **条 → 款 → 项** 层级文档，在正文与关系视图之间联动高亮引用，实时检测断链、自引用与循环引用，并在拖拽调整条款顺序后**原子更新**所有可唯一定位的引用；还可把任意时刻的文档保存为**命名快照**，在「版本对比」视图按稳定节点 ID 比较两个版本的节点增删改、移动与引用差异；「问题与引用」面板还能把检测结果保存为**命名问题基线**，按稳定问题身份（类型 + 源节点 ID + 引用原文 + 同文序次，循环为排序节点 ID 集合）把实时问题分为新增、已解决、仍存在三类比较。右侧「审阅批注」面板支持对条 / 款 / 项正文的任意片段创建批注，批注以**稳定节点 ID + 引用片段 + 前后文锚点**持久化，正文或结构调整后自动尝试重定位，片段缺失或多处匹配时标记待复核并保留候选位置。右侧第 4 个标签「**规范用语审校**」允许维护「规范词 + 多个禁用变体」规则，实时列出命中所在条款与上下文，点击结果定位正文，勾选后批量替换为规范词（提交前逐项核对节点 ID 与原文区间，整批原子替换、可整体撤销 / 重做）。「关系视图」标签内还提供「**引用影响分析**」：选中任一条款后，基于当前确认后的解析图按距离分层列出所有直接 / 间接引用它的源条款并统计各层数量，循环路径自动去重并标注，结果行可点击跳回正文；分析仅用于当前会话，不修改正文、不写入撤销历史。紧邻关系视图的「**路径核对**」标签用于在选定起点条与终点条后，基于当前已确认的条级引用边寻找一条**跳数最少的有向路径**（组合引用的每个已解析目标各作为一条边，同一条对多处引用按正文顺序取最先出现的来源句为证据，循环回指不重复搜索），逐跳展示来源条、引用原句与目标条，点击来源句定位正文，无路径时明确提示，正文或歧义确认变化即按最新解析重算、不展示旧证据。右侧第 6 个标签「**修订沙盒**」为条级删除 / 移位 / 换号提供**预演**：在文档克隆上复用结构改写与问题分析逻辑，按来源节点列出将被改写的引用与将新增 / 消失的断链、循环问题，结果可点击定位当前正文；预演记录生成时的正文版本，正文变化后失效并禁止应用，未失效时可一步应用并整体撤销 / 重做。右侧第 7 个标签「**引用阅读包**」：选定一条后沿当前已确认的引用关系向目标方向逐层收集直接及间接依赖的条款（组合引用的每个已解析目标都参与收集），循环与多路径汇合只收录一次，按原文档顺序完整展示条款及其款、项（保留原编号与正文、不改写原文），并另列收录条款中的断链 / 歧义引用（标明来源、原文与原因），支持一键复制纯文本与从条目跳回正文；正文或歧义确认变化后阅读包立即失效，须重新生成，不能复制旧结果。右侧第 8 个标签「**条款审签**」：对选定条录入审签人并签署，记录该条**稳定 ID、签署时间**与签署当时完整条文（**条号、标题、正文、款、项**）的**内容指纹**；按当前条文重算指纹——正文编辑、结构调整（含拖拽 / 增删 / 换号后的自动引用改写）使受影响条目显示「**待重签**」，未变化的条保持有效，撤销恢复原文时自动恢复有效；列表区分**未签 / 有效 / 待重签**，可跳转对应条并重新签署，已删除条的记录单列且不计入当前统计，审签记录随本地存储与 JSON 一并导入导出，旧数据按空记录加载。「问题与引用」面板还支持对**断链 / 自引用**问题做**例外处置**：审阅者填写理由并标记「**接受例外**」（也可撤销），记录绑定**稳定问题身份**并保存处置时的**来源句原文**；实时重算时身份仍在且来源句一致才显示「✓ 已接受」，来源句变化转「⚠ 待复核」（须刷新来源句证据后重新确认），问题消失转「**已消失**」（留痕可跳转源节点 / 删除）；可按**未处置 / 已接受 / 待复核**筛选并跳转来源正文，处置记录随本地存储与 JSON 一并导入导出，旧数据按空记录加载。

- 纯本地运行，数据保存在浏览器 `localStorage` 与本机文件，无需任何外部账号或网络服务。
- 技术栈：React 18 + TypeScript（Vite）+ Node.js / Express。

## 一条命令启动（推荐 Docker）

需要 Docker 与 Docker Compose（v2）。

```bash
docker compose up --build
```

启动后浏览器访问：

> **http://localhost:3000**

数据持久化在命名卷 `clause-data`（容器内 `/data/state.json`）。停止与清理：

```bash
docker compose down            # 停止（保留数据）
docker compose down -v         # 停止并删除数据卷
```

若要改用目录挂载而非命名卷，可在 `docker-compose.yml` 中把 `clause-data:/data` 改为 `./data:/data`。

## 功能说明

### 1. 粘贴解析
- 点击右上角「粘贴 / 导入」，把条款文本贴入即可。
- 识别规则：
  - `第一条`、`第 12 条`、`第十条之一` 开头的行作为**条**，行内 `【标题】` 作为条标题；
  - 条下的自然段落为**款**；`（一）`、`(一)`、`【一】`、`一、`、`1.` 等形式识别为**项**；
  - 数字支持中文（一、十、二十三、一百零五）、阿拉伯与全角数字；
  - 编号保留原文（支持跳号与「之一/之二」后缀条），款、项按结构位置编号。
- 也可在弹窗中选择之前导出的 JSON 文件恢复数据，或载入内置示例。

### 2. 可折叠层级与正文编辑
- 条可折叠；点击条号（如「第五条」）可直接输入新编号，与目标位置的条交换顺序。
- 点击任意正文即可就地编辑，`Ctrl+Enter` 保存、`Esc` 取消；编辑过程中的连续输入在撤销时合并为一次。
- 条标题栏左侧的 ⠿ 手柄可**拖拽排序**；支持 `+款 / +项 / +条` 新增与删除。

### 3. 引用解析与联动高亮
正文内可识别的引用形式包括：

| 类型 | 示例 |
| --- | --- |
| 条级组合引用 | `第三条、第五条及第七条`、`第三条和第五条`（暂不解析组合中的款、项） |
| 条级闭区间 | `第三条至第五条` |
| 绝对引用 | `第五条`、`第十二条之一`、`第五条第二款`、`第五条第二款第（一）项` |
| 本条 | `本条第三款`、`本条第二款第（二）项` |
| 相邻条 | `前条`、`上条`、`后条`、`下条` |
| 款 / 项相对引用 | `前款第（二）项`、`前项`、`本款第（一）项`、`本项`、`（三）` |

- 组合引用与闭区间解析为**按文档顺序排列的稳定条 ID 集合**：正文高亮与关系视图会把该表达同时关联到全部目标（悬停时所有目标条款一并发光，关系图中每个目标各有一条边）。
- 组合 / 区间中任一目标不存在、或区间端点因同序号后缀条（如「第八条之一」）而有歧义时，整段标记为问题，**问题面板会分别列出已解析目标（可点击定位）与缺失目标（含原因）**。
- 有效引用为绿色，断链红色波浪下划线，自引用黄色，歧义引用蓝色。
- **悬停**正文里的引用：引用本身高亮，目标条款卡片发光。
- **点击**有效引用：滚动并定位到目标节点（组合引用定位到第一个目标）。
- 右侧「关系视图」以环形图展示条级引用边：悬停/点击边与正文双向联动，自引用为黄色自环、处于循环中的边与节点标紫、含断链的条标红。

### 4. 结构调整后的原子改写
- 拖拽排序、点击条号改编号、新增/删除节点后，系统对照调整前的解析结果：
  - 对所有**可唯一定位**的绝对引用一次性、按字符偏移原子改写（如第三条移到末尾，「第三条」自动变为「第五条」），保留原文数字风格（中文/阿拉伯）与「（X）」括号写法及条名；
  - **组合引用 / 闭区间保持原目标集合**：调整后目标仍连续时输出闭区间（如「第二条至第四条」），不连续时展开为顿号列表（如「第二条、第四条、第六条」），并沿用原数字风格；
  - 组合 / 区间的**任一目标被删除或端点有歧义时整段不改写**，并在问题面板列出已解析与缺失目标；
  - 相对引用（本条、前款、前项、后条……）**不改写**，由结构位置自动跟随；
  - 操作结束后弹出提示，告知自动改写数量与未处理数量。
- 整个结构操作与改写（含组合引用的改写）是一次提交，可整体「撤销 / 重做」（按钮或 `Ctrl+Z` / `Ctrl+Y`，`Ctrl+Shift+Z`）。

### 5. 不可唯一定位的引用：只列候选，绝不自动改写
以下情况标记为**歧义**，不会被自动改写，而是在右侧问题面板列出全部候选，由用户单选确认：

- 存在同序号条（如同时有「第八条」与「第八条之一」时，单独写「第八条」）；
- 只给项号、未给款号，且同一条多款下都有该序号项。

确认后该引用按所选目标解析并参与后续结构改写；确认记录会保留在问题列表中（标记「已确认」），可随时跳转目标或撤销确认。

### 6. 问题检测与跳转
右侧「问题与引用」实时统计并分类：

- **断链**：目标条/款/项不存在，或相对引用越过边界（如第一条引用「前款」）；
- **自引用**：引用解析到其所在节点自身（如项内写「本项」自指）；
- **循环引用**：条级有向图上的环（如第六条 ↔ 第七条互相援引），列出完整环路；
- **歧义引用**：见上节。

点击问题中的源句可跳到正文对应句子并高亮；点击目标/环路节点可跳到对应条款。断链与自引用问题还可填写理由「接受例外」（见第 17 节）。

### 7. 问题基线（新增 / 已解决 / 仍存在）
「问题与引用」面板顶部的「**📌 问题基线**」可把**当前检测结果**保存为命名基线，随后把实时结果与任一基线比较：

- 在基线栏输入名称（如「一审基线」）点「**保存为基线**」即自动进入比较；也可随时点击已有基线切换比较、再次点击退出；
- 问题以**稳定身份**对齐：
  - 普通问题 = **问题类型 + 源节点稳定 ID + 引用原文 + 该节点内的同文序次**（同一节点内同原文第几次出现）；
  - 循环引用 = **问题类型 + 排序后的稳定节点 ID 集合**（环路的方向 / 起点变化不另算新问题）；
  - 身份**不含字符偏移**：在引用前后增删文字导致偏移变化时，问题仍判为同一个，不会制造“新增 + 已解决”的假象；
- 比较结果分为三类，可分别筛选：
  - **新增**（绿色）：基线中没有、实时结果中新出现的问题；
  - **已解决**（红色）：基线中有、实时结果中已消失的问题；
  - **仍存在**（黄色）：两侧都有，显示「基线定位 → 当前定位」（条款移动时两处定位不同）；
- **点击任意比较行可跳到现存源句**：新增 / 仍存在跳当前位置；已解决问题按源节点与引用原文在当前文档中重新定位源句（仅引用前文字变化时自动跟随新偏移）；源节点已删除的已解决问题标注「源节点已删除，不可跳转」；
- 基线是保存时刻文档与歧义确认记录的**只读深拷贝**，不随后续编辑变化；**删除基线不影响正文**、确认记录、批注、规则与撤销历史；
- 基线随 `localStorage`、后端文件与 JSON 一并持久化 / 导入导出；比较时一律按基线文档重新分析重建问题身份，旧数据缺少 `issueBaselines` 字段时按**空列表**加载。

### 8. 撤销 / 重做 与 JSON 导入导出
- 顶部「↶ 撤销 / ↷ 重做」，历史最多保留 100 步；连续文本输入自动合并。批注的创建、编辑、删除、候选确认与规范用语规则的增删改、批量替换同样进入撤销历史。问题基线与版本快照为独立的只读留痕，**不进入撤销历史**；条款审签与问题例外处置同样不进入撤销历史——签署只记录指纹、例外只记录身份与来源句证据，正文被撤销 / 重做恢复到处置时版本时记录自动恢复有效 / 已接受。

### 9. 审阅批注

右侧第 3 个标签「**审阅批注**」提供条 / 款 / 项正文片段的批注能力：

- **创建**：在正文非编辑态下用鼠标选取任意片段，松开鼠标后选区上方弹出批注框；输入内容后 `Ctrl+Enter` 或点「添加批注」即可。被批注的片段以下划波浪线标记（浅蓝为已定位、黄色为待复核），片段横跨引用 chip 时 chip 会加虚线描边。
- **编辑 / 删除**：在侧栏批注行点「编辑」改批注正文，「删除」移除（均可随正文撤销 / 重做恢复）。
- **筛选与跳转**：侧栏可按「全部 / ✓ 已定位 / ⚠ 待复核」筛选；点批注行或正文中的批注标记会**滚动定位并高亮**对应片段（所属条折叠时自动展开），同时侧栏同步选中该批注。
- **持久化锚点**：每条批注保存稳定节点 ID、引用片段原文（`quote`）以及前后各 24 字的前后文锚点（`prefix` / `suffix`）。
- **自动重定位**：每次正文编辑或结构调整（拖拽、新增、删除等）后自动尝试重新定位，按顺序使用：
  1. 原节点内精确匹配且**唯一** → 更新偏移，保持锚定；
  2. 原节点内忽略空白 / 标点差异的归一化唯一匹配 → 重新锚定（区间扩展覆盖插入的标点）；
  3. 全文其他节点归一化唯一匹配（如片段随条款移动）→ 锚定到新节点；
  4. 片段出现多处（原节点多处为 `multi-in-node`、全文多处为 `multi-match`）或彻底缺失（节点仍在为 `missing`、节点已删为 `node-missing`）→ 标为**待复核**，并保留按前后文相似度评分排序的候选位置。
- **候选确认**：待复核批注在侧栏列出全部候选（含节点定位与上下文预览），可先点击跳转核对，再点「确认」把批注重新锚定到所选位置；确认后的批注在后续编辑中仍继续参与自动重定位。
- 结构操作后若新增待复核批注，顶部通知条会一并提示数量。

### 10. 版本对比（命名快照）

入口：顶部工具栏的「**版本对比**」标签（「正文编辑」标签可随时切回）。

- 在版本对比页顶部输入名称（如「一审稿」），点击「**📸 保存当前为快照**」，即可把**当前文档**冻结为只读命名快照。继续编辑后再保存一个版本，就能选择任意两个快照进行比较。
- 节点以**稳定节点 ID** 对齐条、款、项，分别标出：
  - **新增**（绿色）、**删除**（红色）、**正文修改**（黄色，行内以逐字增删高亮）、**位置移动**（紫色，显示「旧位置 → 新位置」）；
  - 同一节点同时发生移动与正文修改时，**两类标记同时保留**。
- 「引用」标签页按**源节点 ID + 引用原文 + 同文序次**（同一节点内同原文第几次出现）对齐引用，列出：
  - **新增引用**、**移除引用**、**目标变化**（原文不变但解析到的目标节点不同，含旧目标 → 新目标）；
  - 每条差异都可点「**→ 跳到当前版本**」回到正文对应节点（该节点已在当前版本删除时不显示跳转）。
- 可勾选「仅显示有变化的节点」折叠未变化部分。
- 快照**只读**：保存后不再随后续编辑变化；删除快照**不影响正文、确认记录、批注、规范用语规则与撤销历史**。快照随 JSON 一并导出/导入（含保存时刻的批注与规范用语规则）；旧版导出文件缺少 `snapshots` 字段时按空列表加载。

### 11. 规范用语审校

右侧第 4 个标签「**规范用语审校**」用于维护「规范词 + 多个禁用变体」词表并批量统一用语。

- **维护规则**：点「**+ 新增规则**」增加一条，填一个**规范词**（替换目标）和若干**禁用变体**（用顿号 / 逗号分隔，回车或失焦保存）；可随时编辑、删除，并用 ↑ / ↓ 调整规则顺序。与规范词相同的变体自动剔除。
- **实时命中**：规则或正文每次变化都即时扫描，按条款顺序列出每条命中的**所在条 / 款 / 项定位**与上下文（命中变体高亮），正文内的命中处以黄色波浪下划线标出。
- **重叠消解**：同一位置被多个变体 / 规则命中时，按 **① 起点靠前 → ② 变体较长 → ③ 规则顺序靠前** 的优先级消解，最终命中两两互不交叠。
- **点击定位**：点击侧栏命中行（或正文里的命中标记）会滚动定位到正文对应片段并高亮，所属条折叠时自动展开，正文与侧栏双向联动。
- **勾选批量替换**：逐条勾选或用「全选」，点「**批量替换为规范词**」统一替换：
  - 替换**只处理扫描快照中的已选命中**；提交前逐项核对**节点 ID 与原文区间**（含该节点扫描时的完整正文），**任一项已变化（正文被编辑、节点被删除或结构调整）则整批拒绝**，不会改动任何文字，界面提示重新勾选；
  - 全部有效时**按节点从后向前、单遍替换**，因此替换新生成的文字**不会被递归处理**；
  - 整批替换作为**一步**进入历史，可用顶部「↶ 撤销 / ↷ 重做」（或 `Ctrl+Z` / `Ctrl+Y`）整体恢复；规则的增删改同样可撤销（连续输入合并为一步）。
- 规则与正文一同保存在 `localStorage` 与后端文件，并随 JSON 导出 / 导入；旧数据缺少 `termRules` 字段时按**空规则**加载。

### 12. 引用影响分析（关系视图）

「关系视图」标签下方的「**引用影响分析**」模块用于评估修改 / 删除某一条款的影响面：

- **选择目标**：点击关系图中的任意节点，或在模块下拉框中选择条款，即以其为目标开始分析；被选中的节点在图中以蓝色光环标出；
- **分层结果**：基于**当前确认后的解析图**（含已确认的歧义引用）沿「谁引用了它」反向遍历，找出所有直接及间接引用该条款的源条款，按最短引用距离分层展示（第 1 层为直接引用，其余为间接引用），并统计各层与总数量；
- **跳回正文**：点击任一结果行即滚动定位到正文对应条款，悬停结果行也会在正文中联动高亮；
- **循环去重与标注**：同一条款被多条路径引用时只按最短距离列出一次；处于引用循环上的条款以「↻ 循环」徽标标注，目标自身处于循环中时也会给出提示，页脚同时报告已去重的重复 / 循环路径条数；
- **刷新与清空**：正文编辑后结果会提示「已过期」，点「**刷新**」按最新解析图重新计算，「**清空选择**」清除目标与结果；
- **会话内临时分析**：结果不持久化、不修改正文、不写入撤销历史，仅用于当前会话评估影响范围。

### 13. 引用路径核对（条级最短有向路径）

入口：右侧第 5 个标签「**路径核对**」（紧邻「关系视图」之后；应用访问地址见上文，Docker 一键启动后为 **http://localhost:3000**，本地 `npm start` 同样为 **http://localhost:3000**，开发模式前端在 **http://localhost:5173**）。

紧邻「关系视图」的「**路径核对**」标签，用于回答「从甲条能否沿引用关系走到乙条、最少经过几跳」：

- **选择起点条与终点条**：在两个下拉框分别选择**起点条**与**终点条**（点 ⇅ 可交换两者）。系统立即在**当前已确认的条级引用边**（含已确认的歧义引用；未确认歧义不成边）构成的有向图上，以广度优先搜索寻找一条**跳数最少的有向路径**；等长路径按目标条文档顺序确定，结果可复现。
- **组合引用各目标分别成边**：「第二条、第三条及第五条」「第二条至第五条」等组合 / 闭区间引用解析出的**每个已解析目标各是一条边**，各自独立参与寻路（部分缺失的组合只以已解析目标成边）。路径采用组合边时在证据行标注「组合引用」。
- **多处引用按正文顺序取证**：同一条对在正文中有多处引用时，按**正文顺序**（条序 → 款 / 项位置 → 节点内字符偏移）取**最先出现**且当前正文仍可展示的一处作为证据。
- **逐跳展示**：每一跳列出**来源条**（及其款 / 项定位）、**引用原句**（句中引用原文加粗）与**目标条**（引用精确到款 / 项时同时标明目标节点）；末跳标注「终点」。**点击来源句**即滚动定位并高亮正文中的对应句子，点击来源条 / 目标条 / 目标节点可定位对应正文。
- **无路径明确提示**：两点间不存在有向路径时给出「不存在从 X 到 Y 的有向引用路径」的明确说明，并报告从起点当前可达的条数；起点与终点为同一条时提示「跳数为 0」；起点或终点条款已删除时提示重新选择。
- **循环不导致重复搜索**：BFS 以已访问条款集合收敛，循环回指只计入「去重」统计、不重复展开，因此含环图也能即时给出最短路径。
- **随正文 / 确认实时重算，不展示旧证据**：路径是随当前分析即时计算的纯派生结果，**不缓存**句子与偏移。正文 / 结构编辑（含撤销 / 重做）或歧义确认一旦变化，结果立即按最新解析重建；证据句、句内区间全部取自当前正文，不会残留旧证据。该模块为会话内只读分析，**不修改正文、不写入撤销历史、不持久化**。

### 14. 修订沙盒（条级删除 / 移位 / 换号预演）

入口：右侧第 6 个标签「**修订沙盒**」（应用访问地址见上文，Docker 一键启动后为 **http://localhost:3000**）。

- **预演入口**：选择条款与操作——**删除该条**、**移位**（移动到第 N 位）、**换号**（改为第 N 条，与点击条号改编号同一语义）——点「**开始预演**」；
- **克隆上预演**：预演在当前文档的**克隆**上复用与正文编辑完全相同的结构改写（`applyStructuralChange`）与问题分析（`analyze`）逻辑，**不改动正文、确认记录与撤销历史**；
- **结果按来源节点列出**：
  - **将被改写的引用**：按来源节点分组，逐处显示「原文 → 改写后」（含组合引用整体重渲染的结果）；
  - **不自动改写的引用**：断链 / 歧义 / 目标被删而保持原文的引用及原因（源节点随操作被删除的引用不列入）；
  - **断链 / 循环问题变化**：按稳定问题身份对齐当前与预演结果，分列**将新增**与**将消失**的断链、循环问题；
  - 所有结果行均可**点击定位当前正文**（按引用 key / 问题身份在当前文档中实时重定位）；
- **版本与失效**：预演记录生成时的**正文版本号**（仅正文文档变化时递增，批注 / 规范用语规则提交不影响）与**歧义确认记录**（确认变化会使改写计划失真）；正文或确认记录变化后预演**标记失效并禁止应用**，需放弃后按最新状态重新预演；
- **一步应用**：未失效时点「**✓ 应用此预演**」，该操作及全部引用改写作为**一步**提交，可用「↶ 撤销 / ↷ 重做」（或 `Ctrl+Z` / `Ctrl+Y`）整体恢复；应用结果与直接在正文执行同一结构操作完全一致；
- **会话内临时数据**：预演不持久化、不随 JSON 导出，放弃或应用后即清空。

### 15. 引用阅读包（沿引用方向收集依赖全文）

入口：右侧第 7 个标签「**引用阅读包**」（应用访问地址见上文，Docker 一键启动后为 **http://localhost:3000**）。

- **选择并生成**：在下拉框选择一个**起点条款**，点「**生成阅读包**」。系统沿**当前已确认的引用关系向目标方向**（本条款引用了谁）逐层广度优先遍历，收集起点直接及间接依赖的全部条款：
  - **组合引用的每个已解析目标都参与收集**（如「第二条、第三条及第五条」会把三条都加入）；闭区间同理展开为区间内各条；
  - **循环和多路径汇合只收录一次**：同一条款经多条路径到达时按最短引用距离计一次（起点距离 0、直接依赖 1、间接依赖 2…），页脚报告会合 / 回指去重条数，处于引用循环上的条款加「↻ 循环」徽标；
  - 条内自指（如本条正文以绝对形式写回本条款）不构成条款间依赖，不向外延伸；未确认的**歧义引用不参与收集**（其目标尚未确定），确认后重新生成才按所确认目标延伸。
- **完整原文、按原文档顺序**：收录条款统一按**原文档顺序**排列（不按距离分组），展示完整条款及其全部**款、项**，保留**原编号与正文，不改写原文**；每条标题标注「起点 / 直接依赖 / 第 N 层间接」。条标题、款号（第 N 款）、项号（（N））作为结构编号呈现，正文文字一字不改。
- **另列断链 / 歧义引用，避免摘录被误认为自足**：阅读包末尾单列收录条款中出现的
  - **断链**（目标不存在、越过边界等，含原因）与部分缺失组合引用的**缺失目标原文 / 原因**及**已解析目标**；
  - **未确认歧义引用**（含全部候选定位）；
  - 每条警告标明**来源**（如「第五条第二款第（一）项」）、**引用原文**与**原因**。顶部声明同时提示「摘录可能不完整，并非自足文件」。已确认的歧义不再列入（它已按确认目标正常收录）。
- **一键复制纯文本**：点「**📋 一键复制纯文本**」复制整包纯文本——含标题、起点、生成时间、去重统计、非自足声明、按原文档顺序的完整条款（条 / 款 / 项原编号 + 原文）与末尾断链 / 歧义清单（来源、原文、原因 / 候选），便于粘贴到其他文稿引用。
- **从条目跳回正文**：点击任一收录条款的标题即滚动定位到正文该条；点击任一警告行即跳到当前正文中的**源句**并高亮（按当前解析结果实时重定位，不使用生成时的旧偏移）。
- **变化后重新生成，不能复制旧结果**：阅读包记录生成时的**正文版本号**与**歧义确认记录**。一旦正文 / 结构编辑（含撤销 / 重做）或歧义确认发生变化，阅读包立即标记「**已过期**」：旧摘录仍可见但置灰，**跳转与复制按钮停用**，须点「**重新生成**」按最新分析重建后才能使用；批注 / 规范用语规则等不改变正文的操作不会使其失效。
- **会话内临时数据**：阅读包不修改正文、不写入撤销历史、不持久化、不随 JSON 导出；清空或粘贴导入新文档后即消失。

### 16. 条款审签（条级签署与内容指纹）

入口：右侧第 8 个标签「**条款审签**」，或每条条标题栏上的「**审签**」按钮（已签条文有效时显示「✓ 已签」、条文变化后显示「⚠ 待重签」；应用访问地址见上文，Docker 一键启动后为 **http://localhost:3000**）。

- **录入审签人并签署**：在面板顶部填写审签人（浏览器本地记住上次填写的姓名），在目标条一行点「**签署**」即可；条标题栏的「审签」按钮会自动切到审签面板并定位该条。签署记录该条的**稳定节点 ID、签署时间与审签人**，以及签署当时完整条文（**条号、标题、条头正文、全部款与项**，键序固定的规范化投影）的 **64 位 FNV-1a 内容指纹**。
- **三态实时判定（按当前条文重算指纹）**：
  - **✓ 有效**：记录指纹与当前条文一致，条文未被改动；
  - **⚠ 待重签**：指纹失配——正文编辑、条标题 / 编号修改、拖拽换序、新增 / 删除节点等**结构调整**，以及结构操作触发的**自动引用改写**都会改变相关条的指纹；面板顶栏与侧栏标签同步提示待重签条数；
  - **未签**：当前文档中尚无审签记录的条。
  - 指纹只覆盖被改动条：编辑某一条（含其款、项）不会使其他条变为待重签。
- **撤销恢复原文即恢复有效**：签署本身不写入撤销历史；当正文经撤销 / 重做恢复到签署时的原文，记录指纹重新匹配，自动从「待重签」回到「✓ 有效」，无需重新签署。
- **重新签署**：点条一行的「**重新签署**」（或点条号跳转正文核对后再签）即以当前条文刷新指纹、签署人与签署时间并恢复有效；上一版签署的审签人、时间与旧指纹归档到该条 `history` 中留痕。
- **列表、筛选与跳转**：可按「全部 / 未签 / ✓ 有效 / ⚠ 待重签」筛选，每行显示条号与条标题（点击或「跳转」滚动定位到正文对应条）、审签人、签署时间与指纹后 10 位；正文条标题栏的审签状态与面板实时一致。
- **删除的条不计入当前统计**：条被删除后其审签记录保留在面板底部「已删除条款的审签记录」区（标明稳定 ID、审签人与签署时间），**不计入**顶部总数 / 未签 / 有效 / 待重签统计；撤销删除恢复该条后，记录重新按当前指纹参与判定。
- **持久化与导入导出**：审签记录随 `localStorage`、后端状态文件即时持久化，并随「导出 JSON」的 `signoffs` 字段导出 / 导入（导入后一律按当前条文重新判定，不恢复任何已失效状态）；**旧数据 / 旧导出文件缺少 `signoffs` 字段时按空记录加载**，不影响其他数据。粘贴导入全新文本或载入内置示例时审签记录清空（与旧文档绑定的稳定 ID 不再适用）。

### 17. 断链 / 自引用问题的例外处置

「问题与引用」面板对每条**断链**与**自引用**问题提供例外处置（循环引用是结构性环、歧义引用有单独的确认流程，均不提供例外）。

- **接受例外 / 撤销**：在问题行点「**🛡 接受例外…**」，填写**理由（必填）**后「标记接受例外」即可；问题行显示绿色「✓ 已接受」徽标与理由、处置时间。点「**撤销处置**」删除记录，问题恢复为未处置。处置只记录结论，**不改正文、不进入撤销历史**。
- **记录绑定稳定问题身份与来源句证据**：每条记录保存**稳定问题身份**（类型 + 源节点稳定 ID + 引用原文 + 同文序次，与问题基线同一套身份；不含字符偏移）、源节点稳定 ID 与**处置当时的来源句原文**。
- **实时重算三态**（随正文编辑、结构调整、撤销 / 重做即时判定，不固化任何状态）：
  - **✓ 已接受**：身份仍在当前问题集合中，且**当前来源句与处置时来源句逐字一致**（句前句后增删文字只改变偏移，仍判已接受）；
  - **⚠ 待复核**：身份仍在但**来源句已变化**（句中文字被编辑或被自动改写）；待复核项**必须重新确认**——核对当前正文（可点来源句直接跳转）后点「**重新确认（刷新证据）**」，确认时以**当前来源句刷新证据**并刷新处置时间，理由可沿用或修改；
  - **已消失**：身份已从实时问题中消失（问题被改正、源节点删除或问题类型变化）。已消失记录单列于「**已消失**」筛选：保留处置时来源句、理由与时间，源节点仍在时可「跳转源节点」，源节点已删除标注不可跳转，并可「删除留痕」；撤销改正使同一身份回来且来源句一致时自动恢复「已接受」。
- **筛选与跳转**：面板第二行可按「**未处置 / ✓ 已接受 / ⚠ 待复核 / 已消失**」筛选（与上方问题类型筛选叠加生效，按钮带各状态数量）；侧栏「问题与引用」标签在有待复核项时显示待复核数；所有状态下来源句 / 来源节点均可点击**跳转来源正文**。基线比较视图中的现存问题行同样带有处置入口与状态徽标。
- **持久化与导入导出**：处置记录随 `localStorage`、后端状态文件即时持久化，并随「导出 JSON」的 `issueExceptions` 字段导出 / 导入；**导入后一律按导入文档的当前分析重新判定**已接受 / 待复核 / 已消失，不恢复任何已失效状态；**旧数据 / 旧导出文件缺少 `issueExceptions` 字段时按空记录加载**，不影响其他数据。粘贴导入全新文本或载入内置示例时处置记录清空（与旧文档绑定的稳定身份不再适用）。

## 数据保存在哪里

- 浏览器 `localStorage`（键 `clause-reference-validator:v1`）：编辑时即时保存（每次提交同步写入，连续编辑不受网络状况影响）；
- 后端本地文件：每次变更后约 0.6 秒防抖触发一次服务端镜像保存
  - Docker：`/data/state.json`（持久卷）
  - 本机：`~/.clause-reference-validator/state.json`，可用环境变量 `DATA_DIR` 更改；
- 首次打开若浏览器无数据，会尝试读取后端文件（便于换浏览器共享），否则载入内置示例。
- 后端仅监听本地 HTTP，提供 `/api/state`（GET/PUT）、`/api/health`，不连接任何外部服务。

### 连续编辑的保存顺序与原子性

连续修改条款及随文档保存的记录（确认、批注、规范规则、快照、问题基线、审签、例外处置）时：

- **本地即时生效**：每次提交都同步写入 `localStorage`，不等待任何网络请求；
- **服务端镜像严格串行**：浏览器任一时刻最多只有一个 `PUT /api/state` 在途；发送期间产生的修改会被**合并为最新待写状态**，上一请求结束后只发送这份最新完整状态，并始终按提交顺序同步，因此旧状态不可能越过新状态覆盖服务器文件；
- **服务端原子落盘**：并发保存按请求到达顺序串行执行；每次写入先写一个内容专属的唯一临时文件（`fsync` 后 `rename` 替换 `state.json`），任何时刻读取到的都是**完整的旧文件或完整的新文件**，不会读到半写内容；
- **失败安全**：写入失败发生在替换之前，原有完整文件保留不变，失败请求返回 500；浏览器对网络错误 / 5xx 自动退避重试（重试期间的新编辑会顶替为最新待写状态），重试有上限，放弃后下次编辑仍会继续尝试，不会因一次失败永久停摆；
- 最终服务器文件等于**最后一次成功提交的完整状态**。

## HTTP API

服务端是本地 Express（Docker / `npm start` 均在 `http://localhost:3000`；开发模式前端 5173 通过 Vite 代理转发 `/api`）。所有请求体均为 JSON。

### `GET /api/health`

健康检查，容器 HEALTHCHECK 使用。

```bash
curl http://localhost:3000/api/health
# 200 {"ok":true,"service":"clause-reference-validator"}
```

### `GET /api/state`

读取服务器侧完整状态；尚无文件时 `state` 为 `null`。

```bash
curl http://localhost:3000/api/state
# 200 { "state": { "doc": { "id", "title", "root", "updatedAt" }, "confirmed", ... } }
# 200 { "state": null }
```

### `PUT /api/state`

以请求体**整体替换**服务器状态文件（与页面自动保存同一接口；字段结构同「导出 JSON」中的持久化字段，至少需包含 `doc.title` 与 `doc.root` 数组）。并发请求按到达顺序串行、原子落盘。

```bash
curl -X PUT http://localhost:3000/api/state \
  -H 'Content-Type: application/json' \
  -d '{"doc":{"id":"d1","title":"测试文档","root":[],"updatedAt":1790000000000},"confirmed":{}}'
# 200 { "ok": true, "savedAt": 1790000000000 }
# 400 { "error": "数据格式不合法：需要 { doc: { title, root }, confirmed }" }
# 500 { "error": "保存失败：…" }  // 原文件保持不变，可重试
```

用本地 JSON 导出文件整体写回（例如从备份恢复）：

```bash
curl -X PUT http://localhost:3000/api/state \
  -H 'Content-Type: application/json' \
  --data-binary @backup.json
```

> 说明：`PUT` 是整体替换而非字段合并；浏览器自动保存总是携带完整状态，外部调用也应发送完整状态。JSON 导入导出行为（页面内「粘贴 / 导入」「导出 JSON」，导出包为 `{ app, version, document, ... }` 形态）不受影响。

### `POST /api/validate`

校验导入包结构（不写文件）：请求体需包含 `document.root` 数组。

```bash
curl -X POST http://localhost:3000/api/validate \
  -H 'Content-Type: application/json' \
  -d '{"document":{"title":"t","root":[]}}'
# 200 { "ok": true, "title": "t", "rootCount": 0 }
```

## 本轮变动：连续编辑时服务器镜像不再回退

- **问题**：旧实现中自动保存不等待上一请求，且服务端并发写入共用同一个 `state.json.tmp` 临时文件；两次保存交叠时，旧状态可能在新状态之后落盘造成回退，或因互相截断导致一次写入失败。
- **浏览器端**（`src/lib/storage.ts`）：新增单连接保存队列——同一时刻最多一个 PUT 在途；发送期间产生的修改合并为最新待写状态，请求结束后只发送该完整状态，严格按提交顺序同步；网络错误 / 5xx 自动退避重试（0.4s / 1.2s / 3s，最多 4 次尝试），退避期间的新编辑提前顶替旧状态；本地 `localStorage` 仍每次提交即时写入。`serverStore.save` 的调用约定（`Promise<boolean>`）与 `/api/state` 数据格式不变。
- **服务端**（`server/index.ts`）：写入经 FIFO 队列串行化，保证并发保存的确定顺序；每次写入使用 `.state.<pid>.<uuid>.tmp` 唯一临时文件，`'wx'` 独占创建、写入并 `fsync` 后 `rename` 原子替换 `state.json`；写入失败只清理自己的临时文件、原文件完整保留；进程启动时清理上次崩溃残留的临时文件。GET/PUT 的路径、请求体与响应约定保持不变。
- **交付物**：上述 HTTP API（含调用示例）、`npm run check:storage` / `npm run check:server` 两个自检脚本；Docker 构建与启动方式不变（`docker compose up --build`，卷内 `/data/state.json`）。
